# MOSS Architecture Notes

CIAO uses the vendored `OpenMOSS-Team/MOSS-Audio-Tokenizer-Nano-ONNX` browser
export through ONNX Runtime WebGPU. The production path is intentionally fixed:
one codec profile, one protocol string, and no runtime query-parameter profile
selection.

## Active Shape Contract

- Tokenizer: MOSS Audio Tokenizer Nano.
- Model audio format: 48 kHz, 2 channels.
- Browser capture/playback: mono, duplicated into MOSS stereo input and
  downmixed from MOSS stereo output.
- Token rate: 12.5 Hz from `downsample_rate = 3840`.
- Quantizer: 16 RVQ codebooks, 10-bit code indices.
- CIAO superframe: 7 token steps per 480 ms.
- Encoder input: `[1, 2, 23040]` waveform plus `[1]` input length.
- Encoder output: `[1, 7, 16]` audio codes plus `[1]` code length.
- Streaming decoder input: `[1, 7, 16]` audio codes plus decoder state.
- Streaming decoder raw output: `[1, 2, 26880]`; CIAO trims to 23040 samples.
- DataChannel codec payload: 140 packed bytes per superframe.

The streaming decoder state is mandatory. The metadata declares transformer
offsets and attention K/V caches. CIAO keeps decoder state tensors on WebGPU
buffers where ONNX Runtime Web supports it, so K/V state can feed the next decode
step without a CPU round-trip.

## Dtype Boundaries

The production model profile uses:

- fp32 encoder graph
- fp16 decoder graph
- fp16 decoder K/V cache boundaries
- fp32 public audio output
- int32 offsets, positions, lengths, and token codes

The fp16 decoder is generated by `scripts/convert-moss-webgpu-fp16.py`. It keeps
RoPE and quantizer-sensitive regions on fp32 islands, harmonizes mixed float
inputs with explicit casts, validates ONNX Runtime session creation, and checks
decoder SNR against the fp32 baseline before writing vendored assets.

## Runtime Contract

- WebGPU is required. If `navigator.gpu` or a high-performance adapter is not
  available, the app reports MOSS unavailable and does not emit PCM fallback
  audio.
- Model files are loaded as bytes from the app-managed Cache Storage cache,
  then passed to ONNX Runtime as embedded ONNX model buffers.
- The app verifies exact byte sizes before accepting a cached model asset.
- Service worker updates reload the page only when no call, echo test,
  signaling session, or audio engine is active.

## Regeneration Flow

Run these from the dev container:

```sh
npm run moss:download
npm run moss:optimize
npm run moss:fp16
npm run moss:steps
npm run build
```

`moss:steps` writes only the active step-7 production graphs, embeds external
weight data into the active ONNX files, rewrites the runtime metadata, and
removes transient fp32/source variants from `public/models`.

## Protocol Fit

The active protocol string is `ciao/moss-nano-native/v6/s7/cb16`. Both peers
exchange a `Hello` frame after DataChannel open and reject incompatible codec
shape, bitrate, codebook, or protocol metadata before audio starts.

Audio transport uses:

- unordered unreliable DataChannel (`maxRetransmits: 0`)
- 1-2 MOSS superframes per DataChannel message
- VAD/DTX for silence
- receiver jitter target of 1-3 frames
- simple repeat/fade packet-loss concealment
- receiver feedback with loss, jitter, and playout-buffer depth
